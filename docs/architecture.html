從點擊到最佳化結果

1
瀏覽器以 HTTPS 送出 → 經 Load Balancer / Cloud Armor 過濾（WAF、限流、DDoS）。
2
進 Cloud Run 的 FastAPI：驗證身分與權限、以 Pydantic 嚴格驗證輸入。
3
讀寫資料走 私有連線到 Cloud SQL（不經公網）。
4
吃 CPU 的 MILP 求解 → 丟 Cloud Tasks 背景佇列由 Worker 解，不阻塞 API；前端輪詢或收通知取結果。
5
錯誤進 Sentry、指標／稽核進 Logging/Monitoring；密鑰一律取自 Secret Manager。
資安 · 分層防護（Defense in Depth）

一層被穿，還有下一層

L1 · 傳輸加密通道
  • TLS 1.2+ 全程加密、HSTS 強制 HTTPS、憑證自動更新
L2 · 邊界擋在門外
  • Cloud Armor WAF 規則、DDoS 緩解、IP／地理限制
  • 邊界速率限制，惡意流量進不到應用
L3 · 應用最小信任
  • 身分驗證與授權：帳號登入 ＋ 角色權限（RBAC），取代單一 ADMIN_WRITE_TOKEN
  • 輸入驗證（Pydantic v2）、CORS 白名單、CSRF 防護
  • 求解 DoS 防護：CBC 逾時、並發 semaphore、429 限流
L4 · 資料最後防線
  • 靜態加密（at-rest）＋傳輸加密（in-transit）
  • 私有網路連線（DB 不對公網）、最小權限 DB 帳號
  • 自動備份 ＋ PITR（還原到任一時間點）、還原演練
L5 · 密鑰與存取誰能碰什麼
  • Secret Manager 集中密鑰、可輪替、不落 repo
  • IAM 最小權限服務帳號、prod／staging 環境隔離
L6 · 觀測與供應鏈看得見、追得到
  • Sentry 錯誤、Monitoring/Logging 指標與稽核、告警
  • 確定性引擎：同輸入同輸出，每筆結算可重現、可稽核
  • 供應鏈：依賴／映像掃描、CI 品質閘門（ruff/black/mypy/pytest）
合規 · 資料落地台灣

為什麼堅持台灣境內區域

平台含台電轉供、企業客戶用電等敏感資料。選 asia-east1（彰化）把運算與資料庫都留在台灣境內：對個資法／PDPA、政府與大型企業客戶的資安/合規要求最有底氣，延遲也最低。

資料落地台灣最低延遲PDPA 友善可稽核結算
加分面對能源 B2B 客戶談「資料在哪、誰能碰、怎麼還原、怎麼稽核」時，這套架構每一項都答得出來。
